REMEDIATION 1 — TOKENIZER RESERVATION COST
--------------------------------------------------------------------------------

Root cause:
  Reservation used an indefensible ≤1-token-per-character bound (JS .length =
  UTF-16 units). Tests were tautological.

Fix:
  Server-side gpt-tokenizer with production encoding o200k_base.
  Provider gate + reservedCostMicros share AI_REQUEST_ENVELOPE token ceilings.
  UTF-16 unit cap (maxInputUtf16Units=64000) is DoS prefilter only — not a cost bound.

--------------------------------------------------------------------------------
REMEDIATION 2 — MODEL/ENCODING REGISTRY ENFORCEMENT
--------------------------------------------------------------------------------

Root cause:
  assertO200kModel() was a no-op; AI_MODEL_FLUX_* could map internal keys to
  arbitrary vendor IDs while tokenization still assumed o200k_base.

Fix:
  Explicit server registry binds internal key → vendor ID → encoding.
  Provider config, tokenizer, and dispatch all resolve the same verified metadata.
  Unsupported vendor IDs / unknown internal keys fail closed (not_dispatched).

Limitations (do not overclaim):
  Bound holds only for registry-verified o200k_base mappings (current allowlist:
  gpt-4o-mini, gpt-4o). Exact vendor invoice reconciliation is NOT claimed.
  o200k_base is NOT assumed for arbitrary future OpenAI models.
