PHASE 2 — DESIGN ONLY (PR #2)
--------------------------------------------------------------------------------

Primary: docs/PHASE2_ARCHITECTURE.md
Export:  PHASE2_DESIGN_EXPORT.txt

Core architecture preserved:
- StudentProfile / Attribute / Goal / Observation /
  LearningEvidence / ConceptState / Misconception
- Knowledge: Subject → Topic → Concept
- Current state + evidence history

Final correction pass explicitly specifies:
1. Controlled StudentAttribute registry (typed; not arbitrary profile store)
2. One active attribute per user+key (partial unique index + atomic supersede)
3. Confidence = reliability score (not probability/diagnosis/truth override)
4. Conservative mastery contract (no response→model→MASTERED)
5. No relational IDs in metadata JSON
6. Consent/privacy removed from onboarding questions; notice ≠ legal consent
7. Student context = untrusted data (priority stack)
8. No premature keyword intelligence in Phase 2
9. Server-side onboarding question registry + validation
10. Ownership/deletion contract (user-owned vs catalog vs operational)
11. Implementation sequence 2.0–2.9
12. Expanded testing requirements + Definition of Done

Not in this PR:
- No schema / migrations
- No onboarding UI or APIs
- No assembleAIContext implementation
- No knowledge seed
- No app behavior changes

Open human decisions (Appendix D):
- Final attribute-key naming namespace
- Whether supersededById is mandatory
- Anonymize vs delete for operational logs (legal review)
- When a reliable concept resolver may be added after Phase 2
